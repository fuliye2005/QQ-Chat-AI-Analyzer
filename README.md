# 关于QQ-Chat-AI-Analyzer
这是依赖于Github上的开源项目qq-chat-exporter-master搭建的本地部署的轻量化QQ群聊消息分析工具，出于学习科研目的而开发，可用于生成年度报告等有意思的分析报告。
<br><br>**太过巨大的聊天记录可能会导致分析效果不佳。原项目曾以120MB以内作为本地测试的推荐值，这只是经验值，不是硬性上限。当前程序的网页上传上限为500MB，但实际能否成功分析还会受到JSON内容、消息长度、模型能力、服务商或中转接口限制、网络质量和请求超时设置影响。<br>同时请注意，本工具目前主要适配qce导出的json格式聊天记录，qce流式导出的jsonl在codex辅助合并为单个json后也可以使用。**
<br><br>如果聊天记录实在过大，程序会先按Token预算进行采样，并在超过单次接口容量时自动分段处理；如果仍然超时，可以降低Token预算或并发数。采样和模型能力都会影响最终分析效果。

# 食用指南
> 请详细阅读后进行使用，若有疑问可以联系开发者。阅读大概需要5分钟。
## 这是什么？

这是依赖于***Github***上的开源项目***qq-chat-exporter-master***搭建的**QQ**群聊消息总结分析工具，<br>出于**学习科研目的**而开发。

> 这是***qce***的地址喵~<br>*https://github.com/shuakami/qq-chat-exporter*<br>别忘了点个星星再走哦~

本工具早期主要由**谷歌**研发的***Gemini-3-pro-preview***辅助实现，创作环境为**字节跳动**旗下的***trae IDE***。<br>是**货真价实的AIGC**哦，因为作者本人是**代码苦手**的说~ 当前版本支持OpenAI兼容格式的接口，实际使用的模型由用户配置决定。

**本分支修改：** 在保留原有使用方式和整体风格的基础上，当前版本补充了多年聊天记录分析、按年份生成独立报告、多人集合报告、分片并发分析和分析中间产物保存功能。具体使用方式见下面的“分析参数”和“使用流程”。

此外，本工具调用时可能会把聊天记录完整上传至模型服务提供商，请衡量好**隐私与便利**之间的关系后酌情使用本工具。**若有隐私泄露问题请自行承担责任。**

## 以下是具体的食用教程：

在根目录中双击 *start.bat* 后运行后端服务，打开 *127.0.0.1:5000* 进入前端服务。

### API配置：
负责配置需要调用到的大语言模型，需要用户自行配置模型服务商的**URL地址**、**API key**、**模型名称**。<br>模型名称请填写服务商当前实际提供、并且能够稳定返回JSON的模型；不同服务商和中转接口的可用模型可能不同，下面的历史模型名称不要直接照抄。

网页保存的本地配置会写入根目录的 `config.local.json`，该文件已被 Git 忽略，不会随项目推送。仓库中的 `config.json` 仅作为不含密钥的默认模板。

同时提供了单次分析时可以自由选择模型的选项，以便更好的进行分析。**若不需要该功能，请留空即可。**

### 分析参数：
**Token预算（本分支修改）**：当前界面可调范围是 *128k - 1200k*。（测试环境拉满了）这里的数值是程序用于采样聊天文本的输入预算，不等于模型官方上下文上限，也不等于接口一定可以稳定处理的最大值。
<br>当前程序会把过大的单次输入按约 *900k* Token 的分段预算拆开，这是本项目根据测试设置的保守值。实际可用容量会受到模型版本、服务商、中转层、提示词长度、输出预算和网络超时影响。
<br>建议先从 *128k* 或 *256k* 开始测试，再根据实际响应情况逐步提高。

<br>**本分支修改：** 当输入超过单次接口容量时，程序会自动分段处理；分片分析可以并发执行，并保存已经完成的中间产物，便于在后续汇总失败时继续使用已有结果。

**多年记录分析（本分支修改）**：上传 JSON 后，程序会先识别文件中包含的年份。勾选需要分析的年份后，可以选择“每个年份分别生成”“生成多年集合报告”，或者两种报告都生成。

> **本分支实测环境：** 多年记录测试（`2023`、`2024`、`2025`、`2026` 分年份生成报告）采用 **`gpt-5.6-luna`**。四个年份的独立报告均成功生成；这个结果只代表当时的模型、服务商接口和设备环境，更换模型或服务商后，处理速度、上下文容量、并发稳定性和报告质量可能不同。

**并发请求数（本分支修改）**：用于控制分片同时发送给 AI 的数量，当前界面可设置 *1 - 16* 路，默认值为 *2*。（测试环境也拉满了）并发越高速度越快，但也更容易触发模型服务商的限流，通常建议从 *2 - 4* 路开始。*16路只是程序允许的上限，不代表所有服务商都能稳定承受。*

**动漫小剧场主题**：可以选择预设的两种主题，也可以自定义主题。选择后可以在报告上生成一段将群友带入该主题角色的小剧场，*纯私货，纯整活，ooc可能性存微。*

**最终输出增强**：开启后在报告生成完毕后再度调用一次LLM，将生成的报告发给LLM将其进行可能存在的**HTML格式修复**与**CSS深度美化**。这是额外步骤，会增加请求时间和 Token 消耗；如果加强请求超时或失败，程序仍会保留主体报告。
<br>**本分支实测：** 主体报告可以正常生成；在部分服务商响应较慢时，HTML 加强请求可能超时或连接失败，程序会保留未加强的原始报告。测试没有成功实现加强。

### JSON 文件大小与本地解析性能（本分支实测）

> **重要：** JSON 解析性能取决于本机的 CPU、可用内存、磁盘速度和后台占用。以下数据是在一台 Windows 电脑上于 **2026 年 9 月 2 日** 实测得到的，只能作为当前电脑的参考，不能视为所有设备的固定上限。

测试环境：Intel Core i5-1135G7（8 线程）、16GB 内存（测试开始时剩余可用约 4.5GiB）、Python 3.14.6、Flask 3.1.3、pandas 3.0.5。测试基于一份实际聊天记录生成压力样本，原始大小约 112.7MB，包含 157,636 条消息。压力样本通过重复原始消息数组生成，保持 JSON 结构合法，主要用于测试本地上传和 `/api/inspect` 解析性能；本次没有调用 AI 接口，因此不代表模型或服务商的上下文上限。

| JSON 大小 | 解析结果 | 识别消息数 | `/api/inspect` 耗时 | 进程峰值内存 |
| --- | --- | ---: | ---: | ---: |
| 112.7MB（约 107.5MiB） | 成功 | 157,636 | 约 148 秒 | 约 1.34GB |
| 240MiB | 成功 | 354,120 | 约 301 秒 | 约 2.46GB |
| 360MiB | 成功 | 529,111 | 约 570 秒 | 约 3.56GB |

当前程序的网页上传硬上限为 **500MiB**（代码按 `500 × 1024 × 1024` 字节计算）。在本机已验证成功的最大样本为 **360MiB**，但耗时已经接近 10 分钟；综合耗时和内存占用，日常使用建议控制在 **240MiB 左右**。450MiB 及以上没有在本次测试中继续解析，因此不对其成功与否作保证。

详细的修复、优化和测试记录见 [CHANGELOG.md](CHANGELOG.md)。

### 使用流程：

**第一步：导出数据**
<br>使用 ***QQChatExporter (v5)*** 导出 *JSON* 格式记录。该步骤具体教程参见开头提到的网址。

**第二步：配置 AI**
<br>点击左上角“API 配置”，填入自定义的LLM API配置，以及开启需要的功能。

**第三步：上传分析**
<br>将 JSON 文件拖入中央区域，等待程序解析文件中的年份和消息数量。

**第四步：选择年份和报告方式**
<br>勾选需要分析的年份，再选择生成年度报告、多人集合报告，或两者都生成，然后点击开始 AI 分析。

**第五步：获取报告**
<br>进度条走完后，在结果区域分别下载生成的 HTML 报告。选择逐年生成时，每个年份会对应一份独立报告，不会把几年内容混在一起。
